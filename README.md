# Data Engineering Journey

**Мой путь в Data Engineering: Python, SQL, обработка данных и разработка ETL-пайплайнов.**

Этот репозиторий — история моего практического обучения Data Engineering и подготовки к первой профессиональной роли в этой области.

Моя цель — стать Data Engineer, способным самостоятельно разрабатывать, тестировать и поддерживать надёжные процессы обработки данных, а также эффективно работать в команде разработки.

Основной принцип обучения — **не просто изучать технологии, а применять их на практике**, постепенно переходя от небольших задач к полноценным инженерным решениям.

## Технологический стек

## Структура репозитория

### `data-engineering/`

Основная часть обучения Data Engineering.

Включает практические задания по Python, Pandas и SQL, а также работу над мини-пайплайнами.

Ключевые направления:

- Загрузка, очистка и преобразование данных.
- Проверка схемы и качества входных данных.
- Разделение корректных и некорректных записей (Data Quarantine).
- Логирование, конфигурация и обработка исключений.
- SQL-запросы для аналитики и обработки событий.
- Транзакции, UPSERT и идемпотентность загрузок.
- Инкрементальная обработка данных и Watermarks.
- Проверка корректности результатов загрузки.

### `python-core/`

Дополнительная практика Python, направленная на уверенное владение языком.

Включает:

- Функции, коллекции и структуры данных.
- Обработку ошибок и исключений.
- Чтение и запись файлов.
- Работу с CSV.
- Валидацию и преобразование данных.
- Разделение логики на независимые функции.

### `WC + SR/`

Weekly Challenges и самостоятельные задания для проверки и закрепления знаний.

Цель — научиться решать задачи без готовых шаблонов, анализировать требования и самостоятельно находить решения.

## Избранные практические работы

### 1. Incremental Loading & Watermarks

**[Day 74 — Incremental Loading](data-engineering/day74/queries_day74.sql)**

Практическая реализация инкрементальной обработки событий в PostgreSQL.

Рассматриваемые задачи:

- Отбор новых событий с использованием составного Watermark.
Определение актуального состояния записей.

UPSERT с защитой от перезаписи более свежих данных.

Отделение некорректных событий в quarantine-таблицу.

Транзакционное обновление данных и состояния загрузки.

2. Data Quality & Pipeline Verification

Day 72 — Weekly Challenge

Самостоятельная работа по проверке корректности обработки событий.

Рассматриваемые задачи:

Проверка качества данных.

Сопоставление ожидаемого и фактического состояния таблиц.

Обнаружение отсутствующих и устаревших записей.

Реализация SQL-проверок результатов загрузки.

Формирование статусов прохождения проверок качества.

3. Python Data Processing Pipeline

Day 33 — Pipeline

Учебный мини-пайплайн обработки заказов с использованием Python и Pandas.

Реализованы отдельные компоненты:

Загрузка CSV и проверка входной схемы.

Преобразование типов данных.

Валидация записей и формирование quarantine-набора.

Фильтрация и обогащение данных.

Расчёт агрегированных показателей.

Unit- и integration-тесты с использованием pytest.

Проект носит учебный характер и не является завершённым production-пайплайном.

🧪 Тестирование

В ходе обучения практикую написание автоматизированных тестов с использованием pytest.

В частности, проверяю:

Корректность преобразования данных.

Обработку ошибочных входных значений.

Валидацию схем и конфигураций.

Исключительные ситуации.

Взаимодействие нескольких компонентов обработки данных.

Примеры тестов находятся в data-engineering/day33/tests/.
